# Changelog

## [2.4.0] - 2026-11-06

- **Simulation and Write to PLC** — the row **Simulation** of the Connection view (also **CMsoft Import for Melsec: Simulation and PLC Actions**) shows what runs and offers the actions that fit: **Start Simulation** starts the **PLC simulation** of GX Simulator3 with the project (GX Works3 writes it), and a **system simulation** started in GX Works3 or GX Simulator3 is found - the Open Interface cannot start it; **Stop Simulation** ends either, and answers GX Simulator3's own questions about ending the simulation. An HMI (WinCC Unified, GOT) or another SLMP client reaches both on `127.0.0.1:5511`. Writes go to the simulation that GX Works3 is connected to (**Connect Simulation**) - a system simulation that runs but is not connected is no target, and the AI tools say how to connect it. **Write to PLC** writes the parameters, the program and the global labels (without the files of the SD memory card unless asked): to a simulation with STOP, write, RESET and RUN, so that the new parameters take effect and the simulated CPU runs the project; to a real PLC only after a warning dialog, and its operating state stays as it is. **Remote RUN / STOP / RESET** and **Read / Write PLC Devices** (SLMP, the MC protocol: `D100:4`, `M0:16`, `D200:2:float`, `M10=true` ...) complete it. The status, starting and stopping a simulation and reading devices are FREE; writing to the PLC, remote operations and writing devices are PRO.
- **MCP server for AI agents** — the extension runs a localhost-only MCP server (Streamable HTTP, Bearer token) with all its tools, for Claude Code, Claude Desktop, Cursor and other MCP clients; VS Code Copilot finds it by itself (VS Code 1.99 and later). The endpoint and its token are written to `.melsec/mcp.json` while it runs; the row **MCP Server** of the Connection view (**CMsoft Import for Melsec: Toggle MCP Server**, setting `melsecImport.mcp.enabled`, on by default) switches it. Long calls (a rebuild, a project import, a write to the PLC) send progress so that the client does not give up. The tools are PRO, like the Copilot tools.
- **Seven new AI tools** (Copilot, MCP, CLI bridge) — `melsec_plc_status`, `melsec_start_simulation`, `melsec_stop_simulation`, `melsec_download_to_plc`, `melsec_plc_run_state`, `melsec_read_devices` and `melsec_write_devices`, and the CLI commands `plc_status`, `start_simulation`, `stop_simulation`, `download_to_plc`, `plc_run_state`, `read_devices`, `write_devices`: an agent builds the project, starts the PLC simulation (or uses the system simulation the engineer started), writes the project to it and tests the program by writing inputs and reading outputs. **Safety:** the tools always reach the simulation; a real PLC only after the engineer allowed it in the row **PLC Download for AI** (setting `melsecImport.lmTools.allowPlcDownload`, off by default) - and even then a write never changes the operating state of the PLC by itself.
- **Projects with GX Works3 user authentication open** — *Open Project* (also `open_project` of the CLI bridge and the Copilot tool `melsec_connect`) failed for a project protected by GX Works3's user authentication with *LoginFailed (code 4612)*, so such a project could not be imported or built. VS Code now asks for the GX Works3 user name and password in two input boxes (the password masked) and opens the project with them. The login is typed by the local user also when an AI tool or a script opens the project - it never passes through the tool, is not logged and is not kept: the next *Open Project* asks again. A wrong login is named as such (*GX Works3 refused the login - wrong user name or password*), a cancelled one too.
- **New Project** — **CMsoft Import for Melsec: New Project** (also in the empty *Project Structure* view), the CLI command `create_project` and the Copilot tool `melsec_create_project` create an empty GX Works3 project for a standard CPU of the MELSEC iQ-R (`R00`-`R120`, `R04EN`-`R120EN`), iQ-F (`FX5U`, `FX5UJ`, `FX5S`) or iQ-L series (`L04H`-`L16H`) with the program language of its first program (Ladder, ST or FBD/LD), save it as a new `.gx3` file and connect to it - the start of a project that an AI agent writes from a specification. An existing file is never overwritten.
- **Instructions for AI agents: GX Works3 projects and their XML files** — *Prepare Workspace* adds `.github/instructions/melsec-import-xml.instructions.md`: how a GX Works3 project is organized (execution types, tasks, FB and FUN files, label lists, module labels, safety objects), how the imported XML files are built (the PLCopen envelope and the Mitsubishi extensions, data types, global labels with devices, retentive and constant lists, POU interfaces, ST, ladder as a MELSEC instruction list, FBD/LD, tasks), the MELSEC devices, and how to write a project from scratch that GX Works3 builds - with the build errors met on the way and their fixes. Ladder is written as instruction lists without FB or function calls: GX Works3 refuses an imported ladder POU that declares or calls an FB instance. `AGENTS.md`, `CLAUDE.md` and `.github/copilot-instructions.md` point to it; the CLI instructions describe `create_project`.
- **Problems of imports and exports in the Problems panel** — an object that GX Works3 did not import, or imported with a warning, is an entry of the Problems panel (source *Import from GX Works3*): an object without a file in the read-only document *Import from GX Works3.log* with the whole message, otherwise on its file. It stays until the object is imported again; Import Project replaces all entries. A file that GX Works3 refused on export is an entry on that file (source *Export to GX Works3*) until it is exported again. The notifications of an import or export with failures have **Show Problems**. Commands, Copilot tools and the CLI bridge fill the list alike; FREE refusals add nothing.
- **Build errors in the Problems panel** — *Build Project* and *Rebuild Project* (also the Copilot and MCP tools and the CLI bridge) put every error and warning of the GX Works3 Output window into the Problems panel (source *Build in GX Works3*): on the XML file of its POU in the workspace, or - without such a file - in the read-only document *Build in GX Works3.log*. The next build replaces them; a clean build clears the list.
- **Build messages of a long Output window** — with tens of messages (23 check warnings of a rebuild on the test PC) *Build Project* and *Rebuild Project* (also `build` / `rebuild` of the CLI bridge and the Copilot tools) returned no message, only *Could not read GX Works3 Output window details: MelsecOutputScraper.exe did not finish in time*: the reader's answer filled the pipe while the bridge waited for the reader to end. The answer is now read while the reader runs, and the reader may take up to 30 seconds.
- **What's New** — after an update the extension opens a *What's New* tab once: the new functions of the version, each with a link to its section of the user manual, and the change log. **CMsoft Import for Melsec: What's New** opens it again; a new installation and a restart of the same version do not open it.
- **Refresh license status with an active license** — in a VS Code profile without a recorded acceptance of the license terms it answered *Accept the license terms (EULA) first*, but the license panel shows the terms only without a license. It now renews the key and reports the license as up to date; started from the Command Palette, its message no longer gets lost while the panel opens.

## [2.3.0] - 2026-10-24

- **Open Project with a forward-slash path** — `open_project` of the CLI bridge and the Copilot tool `melsec_connect` failed for a path such as `E:/Projects/Pump.gx3` with *Internal (code -999)* of the Open Interface, and answered only *Failed to open GX Works3 project*; the path is now handed to GX Works3 with Windows separators, and a failure names the reason (*Failed to open GX Works3 project: …*).
- **CLI Bridge row in FREE** — the Connection view showed `On` although the CLI bridge does not run without PRO; it now shows `On (requires PRO)`, as CMsoft Import for Step7 does.
- **License check after an update** — the first start after an update of the extension asks the license server about the license once, as the license panel does when it opens: a renewed term, changed PRO features or a revoked license arrive right away, not only in the last seven days of the license. Offline, the next start asks again. **Privacy Policy 1.3** names the check.
- **FREE plan: 10 objects per import or export, 15 minutes between operations** — the same limits as in CMsoft Import for TiaPortal. In the FREE plan one operation (one command such as Import Project, the import of a folder of the tree or of one object, an export of a file, a folder or all files, or one AI tool call) transfers at most 10 objects in either direction; the import from GX Works3 was unlimited before. The next import or export is available 15 minutes after the previous one has ended, in every VS Code window and after a restart. An operation over the limit is refused before anything is read or sent - a refused **Import Project** removes no files - and the dialog says what the limit is and when the next operation is possible. The export limit now counts the objects in the files to be sent, not the number of files. PRO and the free trial have no limits.
- **License dialog: one button** — the dialog of a PRO function or of a FREE limit has one button, **Buy License**, which opens the license panel (buy a subscription, start the free trial or activate a license key). The second button **Activate License** and the direct jump to the purchase page are gone.
- **Terms of Sale 1.3 and purchase wording** — the Terms of Sale (§1, §5), the README, the user manual and the purchase step of the license panel name the way PRO is sold: a monthly or yearly subscription that renews automatically until cancelled.
- **A GX Works3 that ended is no longer taken for a connected one** — when GX Works3 and its Open Interface server (`GXW3OpenIFCOM.exe`) ended while a project was open (a crash, the Task Manager), the Open Interface answered every call with empty results that counted as successful: *Open Project* could report **Connected** without starting GX Works3, an export "succeeded" without reaching GX Works3, and **Import Project** moved the files of the global labels and data types of the workspace to the recycle bin as orphans. Now the first command that needs GX Works3 closes the connection with *GX Works3 does not answer any more* and does not run; an import or an export that was running transfers nothing more, and **Open Project** starts GX Works3 anew in the same window, without a reload. **Import Project** also stops when GX Works3 answers none of the object lists, and removes no file when GX Works3 lists no objects at all (user manual, sections 6.6 and 7.6).

## [2.1.0] - 2026-10-17

- **New name: CMsoft Import for Melsec** — the extension formerly called *Melsec GX Import* is now *CMsoft Import for Melsec*: the activity bar view, the commands (*CMsoft Import for Melsec: …*), the Output channel, the walkthrough, the chat participant (`@melsec` keeps its handle) and the user manual carry the new name. The extension ID (`MariuszCzyrnek.melsec-import`), the command IDs and the settings stay the same.
- **New icons** — the CMsoft cloud with *cm* and *Import* in red; in the activity bar the same cloud with an *M*, in the colour of the theme.
- **License change** — from this version the extension is commercial software under the [End User License Agreement](LICENSE.md). Version 1.0.0 was released under the MIT License and remains MIT-licensed.
- **FREE and PRO** — opening and browsing projects, the import from GX Works3, build and save stay free; the export to GX Works3 is free for up to 10 objects per operation. **PRO** unlocks the unlimited export, the Copilot tools and the `@melsec` chat participant, the CLI bridge and Prepare Workspace. The license panel (**CMsoft Import for Melsec: Manage License / Subscription**) offers a free 14-day trial and the purchase of a monthly or yearly subscription, with a 14-day money-back guarantee; each license covers one computer ([Terms of Sale](TERMS.md)). The license is shown in the **CMsoft** item in the status bar — one item for all installed CMsoft extensions — and in the *Connection* view.
- **User manual inside the extension** — the English user manual (installation, GX Works3 Open Interface, every function with screenshots, a worked example with real build errors, Copilot tools, CLI bridge, settings, license, troubleshooting) opens in VS Code, offline: **CMsoft Import for Melsec: Open User Manual**, **CMsoft Import for Melsec: Search the User Manual** (jumps to a chapter or section), the walkthrough, two links in the empty *Project Structure* view, and an **Open Help** button on the error message of a failed *Open Project* / *Attach to Open Project*. The **CMsoft** item in the status bar and **Help: CMsoft Manuals…** list the manuals of all installed CMsoft extensions.
- **Smaller download** — the package no longer contains the sources and the macOS, ARM64 and 32-bit binaries of its native modules.
- **Prepare Workspace next to the other CMsoft extensions** (CMsoft workspace protocol) — the instructions for AI agents are in files named after the extension (`.github/instructions/melsec-import.instructions.md`, `melsec-import-cli.instructions.md`, `Tools/melsec_cli_example.py`); `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, `.gitignore` and `Tools/README.md` get one section of CMsoft Import for Melsec next to the sections of the migrator to TIA Portal and CMsoft Import for TiaPortal, so a shared workspace holds the instructions of all of them. Running it again updates the extension's own section and files; your text outside the sections, and files you made your own, stay. Unchanged copies of the templates of earlier versions are replaced. `UserFiles/.gitkeep` is now part of the package.
- **The CMsoft shop has its own address** — the README, the user manual and the documents that ship with the extension (End User License Agreement, Terms of Sale, Privacy Policy) point to <https://shop.cmsoft.com.pl>: the extension's page, the plans and the Terms of Sale, Refund and Privacy policies. The terms of the documents are unchanged.
- **The disclaimer of liability in the user manual and the walkthrough** — the user manual sums up sections 12–14 of the End User License Agreement in section 14.10 (*Disclaimer of liability*), warns in section 2.7, says in section 11.9 that code written by an AI assistant is not reviewed or verified by CMsoft, asks you to work on a copy of the project in the worked example (chapter 10) and says in section 12.3 that the token of the CLI bridge works like a password; the *Get Started* walkthrough has a step **Work safely**. The README's *Disclaimer of Liability* names the AI assistants and the project backups and follows the agreement: liability is excluded or limited to the extent permitted by law, and liability that the law does not allow to exclude and the rights of consumers are not affected. `@melsec` and the instructions of **Prepare Workspace** tell assistants to leave safety programs alone unless you confirm an independent review. The terms of the documents are unchanged.
- **Fixes:**
  - The README and the user manual no longer assume the sources of the extension: Node.js and the .NET 8 SDK are no longer listed among the requirements (they were needed only to build the extension), the installation no longer mentions a build from source, the helper script `melsec-cli.js` runs on the runtime of VS Code (the `melsec` PowerShell function of section 12.4 of the manual, also in the agent instructions of **Prepare Workspace**) instead of a separately installed Node.js, the example scripts of the manual are printed in full instead of pointing to the repository, and Appendix D builds the demo project from the listings in it. The *VS Code* and *License* badges of the README no longer break when the package is built, and a release copies the license, terms, privacy and security documents to the public documentation repository, which the links of the README on the Marketplace page lead to. A missing bridge DLL asks to reinstall the extension instead of naming a build command.
  - *Import Project* through the Copilot tool or the CLI no longer deletes the folder `FB` (function blocks, functions and your own files): the cleanup of orphaned files compares the paths the import writes, moves only `.xml` files to the recycle bin and keeps every other file. It now also runs for **Import Project** in the views, as the setting describes, and is skipped when the object list from GX Works3 is incomplete.
  - Importing a single function block, function, label list or data type through the Copilot tool or the CLI works (the object is looked up in the project), and a failed import no longer replaces the workspace file with an empty one.
  - A click on an object in the *Project Structure* view opens its file instead of importing it over local changes.
  - A GX Works3 that was closed or crashed is detected (*Connection was lost*); *Open Project* attaches to a GX Works3 that already holds the project instead of opening a read-only second copy; a read-only project is marked and warned about; *Attach to Open Project* asks which project when several GX Works3 windows are open.
  - Build messages are read only from the GX Works3 window of the open project - never from another GX Works3. The free label memory that GX Works3 lists after a rebuild is logged as information, not as a warning; the log names the return code of a failed build (`returnCode=6816 (ProjectBuildFailed)`).
  - *Build* on a project that needs a rebuild offers **Rebuild Project**; *Rebuild* on a project that was never built uses a new label assignment.
  - The Copilot tools ask before they export, save or import (`melsecImport.lmTools.autoConfirmExports` skips it for export and save); `@melsec` runs the tools the model calls; `melsec_refresh` and the CLI command `refresh` re-read the project.
  - CLI: the helper script sends its parameters (`key=value` or `--key value`) and exits with 1 on failure; `GET /health`; `import_object` needs only `objectName`.
  - *Open Project* shows a progress notification; *Save Project* confirms; failed exports are reported as warnings or errors; *Open Settings* and *Import Object* from the Command Palette work; *Clear Logs* stays cleared; Save/Close/Disconnect show only while a project is open; log lines keep the text after a path.
  - Settings without a function removed (`importFormat`, `includeComments`, `excludeSystemObjects`, `dotnetPath`, `lmTools.maxFixIterations`); `autoConnect` reopens the last project of the workspace.
