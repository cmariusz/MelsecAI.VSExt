# Changelog

## [2.2.0] - 2026-10-17

- **README: website link** — the README starts with a link to [www.cmsoft.com.pl](https://www.cmsoft.com.pl); its *FREE and PRO* table is headed like in the other CMsoft extensions.

## [2.1.0] - 2026-10-17

- **New name: CMsoft Import for Melsec** — the extension formerly called *Melsec GX Import* is now *CMsoft Import for Melsec*: the activity bar view, the commands (*CMsoft Import for Melsec: …*), the Output channel, the walkthrough, the chat participant (`@melsec` keeps its handle) and the user manual carry the new name. The extension ID (`MariuszCzyrnek.melsec-import`), the command IDs and the settings stay the same.
- **New icons** — the CMsoft cloud with *cm* and *Import* in red; in the activity bar the same cloud with an *M*, in the colour of the theme.
- **License change** — from this version the extension is commercial software under the [End User License Agreement](LICENSE.md). Version 1.0.0 was released under the MIT License and remains MIT-licensed.
- **FREE and PRO** — opening and browsing projects, the import from GX Works3, build and save stay free; the export to GX Works3 is free for up to 10 objects per operation. **PRO** unlocks the unlimited export, the Copilot tools and the `@melsec` chat participant, the CLI bridge and Prepare Workspace. The license panel (**CMsoft Import for Melsec: Manage License / Subscription**) offers a free 14-day trial and the purchase of a subscription or a one-time license, with a 14-day money-back guarantee; each license covers one computer ([Terms of Sale](TERMS.md)). The license is shown in the **CMsoft** item in the status bar — one item for all installed CMsoft extensions — and in the *Connection* view.
- **User manual inside the extension** — the English user manual (installation, GX Works3 Open Interface, every function with screenshots, a worked example with real build errors, Copilot tools, CLI bridge, settings, license, troubleshooting) opens in VS Code, offline: **CMsoft Import for Melsec: Open User Manual**, **CMsoft Import for Melsec: Search the User Manual** (jumps to a chapter or section), the walkthrough, two links in the empty *Project Structure* view, and an **Open Help** button on the error message of a failed *Open Project* / *Attach to Open Project*. The **CMsoft** item in the status bar and **Help: CMsoft Manuals…** list the manuals of all installed CMsoft extensions.
- **Smaller download** — the package no longer contains the sources and the macOS, ARM64 and 32-bit binaries of its native modules.
- **Prepare Workspace next to the other CMsoft extensions** (CMsoft workspace protocol) — the instructions for AI agents are in files named after the extension (`.github/instructions/melsec-import.instructions.md`, `melsec-import-cli.instructions.md`, `Tools/melsec_cli_example.py`); `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, `.gitignore` and `Tools/README.md` get one section of CMsoft Import for Melsec next to the sections of the migrator to TIA Portal and CMsoft Import for TiaPortal, so a shared workspace holds the instructions of all of them. Running it again updates the extension's own section and files; your text outside the sections, and files you made your own, stay. Unchanged copies of the templates of earlier versions are replaced. `UserFiles/.gitkeep` is now part of the package.
- **The CMsoft shop has its own address** — the README, the user manual and the documents that ship with the extension (End User License Agreement, Terms of Sale, Privacy Policy) point to <https://shop.cmsoft.com.pl>: the extension's page, the plans and the Terms of Sale, Refund and Privacy policies. The terms of the documents are unchanged.
- **The disclaimer of liability in the user manual and the walkthrough** — the user manual sums up sections 12–14 of the End User License Agreement in section 14.10 (*Disclaimer of liability*), warns in section 2.7, says in section 11.9 that code written by an AI assistant is not reviewed or verified by CMsoft, asks you to work on a copy of the project in the worked example (chapter 10) and says in section 12.3 that the token of the CLI bridge works like a password; the *Get Started* walkthrough has a step **Work safely**. The README's *Disclaimer of Liability* names the AI assistants and the project backups and follows the agreement: liability is excluded or limited to the extent permitted by law, and liability that the law does not allow to exclude and the rights of consumers are not affected. `@melsec` and the instructions of **Prepare Workspace** tell assistants to leave safety programs alone unless you confirm an independent review. The terms of the documents are unchanged.
- **Fixes:**
  - The README and the user manual no longer assume the sources of the extension: Node.js and the .NET 8 SDK are no longer listed among the requirements (they were needed only to build the extension), the installation no longer mentions a build from source, the helper script `melsec-cli.js` runs on the runtime of VS Code (the `melsec` PowerShell function of section 12.4 of the manual, also in the agent instructions of **Prepare Workspace**) instead of a separately installed Node.js, the example scripts of the manual are printed in full instead of pointing to the repository, and Appendix D builds the demo project from the listings in it. The *VS Code* and *License* badges of the README no longer break when the package is built, and a release copies the license, terms, privacy and security documents to the public documentation repository, which the links of the README on the Marketplace page lead to. A missing bridge DLL asks to reinstall the extension instead of naming a build command.
  - *Import Project* through the Copilot tool or the CLI no longer deletes the folder `FB` (function blocks, functions and your own files): the cleanup of orphaned files compares the paths the import writes, moves only `.xml` files to the recycle bin and keeps every other file. It now also runs for **Import Project** in the views, as the setting describes, and is skipped when the object list from GX Works3 is incomplete.
  - Importing a single function block, function, label list or data type through the Copilot tool or the CLI works (the object is looked up in the project), and a failed import no longer replaces the workspace file with an empty one.
  - A click on an object in the *Project Structure* view opens its file instead of importing it over local changes.
  - A GX Works3 that was closed or crashed is detected (*Connection was lost*); *Open Project* attaches to a GX Works3 that already holds the project instead of opening a read-only second copy; a read-only project is marked and warned about; *Attach to Open Project* asks which project when several GX Works3 windows are open.
  - Build messages are read only from the GX Works3 window of the open project - never from another GX Works3. The free label memory that GX Works3 lists after a rebuild is logged as information, not as a warning; the log names the return code of a failed build (`returnCode=6816 (ProjectBuildFailed)`).
  - *Build* on a project that needs a rebuild offers **Rebuild Project**; *Rebuild* on a project that was never built uses a new label assignment.
  - The Copilot tools ask before they export, save or import (`melsecImport.lmTools.autoConfirmExports` skips it for export and save); `@melsec` runs the tools the model calls; `melsec_refresh` and the CLI command `refresh` re-read the project.
  - CLI: the helper script sends its parameters (`key=value` or `--key value`) and exits with 1 on failure; `GET /health`; `import_object` needs only `objectName`.
  - *Open Project* shows a progress notification; *Save Project* confirms; failed exports are reported as warnings or errors; *Open Settings* and *Import Object* from the Command Palette work; *Clear Logs* stays cleared; Save/Close/Disconnect show only while a project is open; log lines keep the text after a path.
  - Settings without a function removed (`importFormat`, `includeComments`, `excludeSystemObjects`, `dotnetPath`, `lmTools.maxFixIterations`); `autoConnect` reopens the last project of the workspace.
